# 新しいサイトを作るときの、引き継ぎメモ（補助金ネットで得たノウハウ）

別のサイト（例：全国のフリーマーケット情報）を、同じ進め方で作るための、まとめ。
元の作業メモは、このリポジトリの `CLAUDE.md`（仕組みの細部）。ここには、「なぜそうしたか」と「つまずいたところ」を書く。

## 1. 補助金ネットは、どう作ったか（経緯）
1. 最初は、国の補助金の公開データ（jGrants）を、検索できるようにしただけの小さなサイトだった。
2. 検索だけでは、見に来る理由が弱いので、次の順に、足していった。
   - 解説ページ（基礎知識・特集・ニュース・ブログ）→ 検索エンジンから入ってくる入口を増やす
   - 地域ページ（都道府県・市区町村）→ 「自分の地域の制度」という、強い検索の入口
   - 制度ガイド（自治体の制度ごとの詳しいページ）→ 公式ページの事実だけで書く
   - 独自のデータ（件数・傾向・変更履歴）→ このサイトにしかない情報
   - 利用者向けの機能（保存・マイページ・ログイン）→ 「また来る理由」
3. 毎日、自動で更新する（GitHub Actions → Cloudflare Workers）。手作業の更新は、ほぼない。

## 2. 構成（変えずに使えるもの）
- **静的サイト生成**：`scripts/`（Node ESM）が `public/` の HTML を作る。Cloudflare Workers が、静的ファイルと `/api/*` を配る。
- **毎日の自動更新**：`.github/workflows/cloudflare.yml`（毎日 21:12 UTC＝朝6:12 JST、手動実行も可）。build.command で、データ取得→ページ生成→後処理→デプロイ。
- **後処理は、冪等**（何度実行しても同じ結果）にする。順番は、`package.json` の `build:grants` に書く。
- **ナビは、1か所で定義**（`scripts/lib/nav.mjs`）して、`apply-nav` で全ページに反映。生成ページは、同じ定義を読む。
- **サイトマップの更新日**は、ページの本文（`<main>`）のハッシュで決める。本文が変わったページだけ、日付が進む。
- **トップの一覧は、ブラウザで JSON を読んで描く**＋ビルド時に、同じ内容を書き込む（prerender）。コミットするときは、「読み込み中…」の状態にしておく。
- **会員機能は、あとから足せる作り**：データの置き場を1か所（`mypage-store.js`）にまとめ、ログインなし（localStorage）→ ログインあり（Cloudflare D1）に、差し替えた。ログイン方式は、Google ログイン（サーバーで ID トークンを検証）。D1 のバインディングと Secret がなければ、機能は自動でオフ。

## 3. データの質の守り方（いちばん大事）
- **事実だけを書く**。推測・一般論・他の知識による補足は、書かない。書けないときは、書かない（ページにしない）。
- 数字と引用は、**取得した本文と機械で突き合わせる**（`verify-program-details.mjs`）。合格したものだけ、ページにする。
- **古い・終わった・中身が薄い**ものは、ページにしない（reason を付けて skip）。
- **毎週、公式ページを取り直して、変化を検出**する（`check-program-sources.mjs`）。取得できない状態が続く・期間が終わった → 非公開。本文と合わなくなった → 注意書き。
- 取得できなかったもの（404・通信エラー）は、一覧に残して、あとで直す（`program-unfetched.json`）。
- 出典を、はっきり出す（出典・更新方針のページ）。公式の情報への、リンクを必ず付ける。

## 4. 利用者向けの設計で、効いたこと
- **入口を整理する**：初めての人が9割なので、「最初に何をするか」を、1画面で決められるようにする（検索1本＋入口4つ＋「事業者／個人」の切り替え）。
- **トップから2クリック以内**に、すべてのページへ行ける（リンクの深さを、スクリプトで計測する）。
- メニューは、「探す → 管理する → 学ぶ → サイトについて」の4つ（GrantWatch を参考）。
- **数字を見せる**（掲載数・自治体数）。信頼につながる。数字は、自動で更新する。
- 利用規約・プライバシーポリシーは、会員機能を出す前に、専門家に確認してもらった。
- 使い方ページを、機能が増えるたびに更新する（毎朝の定期タスクで、必要なときだけ）。

## 5. 作業の進め方（Claude Code との付き合い方）
- **`CLAUDE.md` に、作業の決まりと、仕組みの要点を書き続ける**。新しいセッションは、これを読んで、続きから始められる。
- **デザインは、先に画像で案を見せる**（Playwright で HTML を撮る）。案を選んでから、実装する。
- **1回の変更ごとに、テストを回して、コミット→決まったブランチへプッシュ**。
- **大きな書き起こしは、担当に分けて並行する。ただし、同時に動かすのは、4つまで**（8つ同時に動かして、週の利用上限に当たって止まった）。担当ごとに、作業用の場所を分け、検証スクリプトに通ったものだけを、統合する。
- **画面は、実際のブラウザで確認する**（Playwright）。見た目・クリック・スマホ幅（390px）。
- 変更前後に、テストを実行する。テストの失敗は、直すか、原因を説明する。
- 毎日の保守は、**定期タスク**にする（使い方ページの更新など）。

## 6. つまずいたところ（先に知っておくと、早い）
- この作業環境では、外への通信は、プロキシ経由。Node の `fetch` は、`NODE_USE_ENV_PROXY=1` が必要。curl は、そのまま通る。
- 国のデータ（jGrants）は、この作業環境から取れない（本番の Actions でだけ取れる）。データがないときの動きも、決めておく。
- 生成物の、空白だけの差分は、戻す（`apply-nav` を回すと、フッターのインデントが増える癖があった）。
- Google ログインを使うなら、CSP に、Google の許可（script / frame / connect / style）が要る。
- Cloudflare の変数は、「Secret」にする。画面だけで足したバインディングは、次のデプロイで外れることがある。`wrangler.jsonc` に書く。
- メール送信は、Cloudflare の Email Service で、ドメインの有効化が要る。いつでも止められるよう、フラグ（`NOTIFY_ENABLED`）を付けた。
- 週の利用上限は、並行の担当が多いと、すぐに尽きる。

## 7. 「全国のフリーマーケット」に、置き換えるときの、考えどころ
補助金と違って、**情報の寿命が短く、日付と場所が中心**になる。

| 補助金ネット | フリマサイト（案） |
|---|---|
| 制度（募集期間・上限額） | 開催（開催日・時間・場所・出店料・出店の申込み・雨天の扱い） |
| 地域別（都道府県・市区町村） | 地域別、**開催日別（今週末・来月）**、種類別（フリマ・蚤の市・骨董市・手作り市・農産物市） |
| 締切が近い順 | **開催日が近い順**、「今週末」 |
| 制度ガイド（公式の事実だけ） | 開催ごとの詳細ページ（主催者の公式の事実だけ） |
| 毎週の公式ページの確認 | **毎日（または、開催前に）確認**：中止・延期・日付の変更が多い |
| 保存・締切カレンダー | 行きたい／出店したい、**開催日のカレンダー**、地図 |
| 事業者／個人 | **来場者／出店者**（出店者向けに、出店料・申込み方法・持ち物） |

- **情報源の、権利と規約を、先に決める**：主催者や自治体の公式ページ・公式の公開データを使う。他サイトの掲載内容の複製は、しない。出典と、公式へのリンクを付ける。取得するときは、robots.txt と、利用規約を守り、頻度を抑える。掲載の削除依頼の窓口を、用意する。
- **日付と場所を、構造化して持つ**：ISO の日付、開催の繰り返し（毎月第2日曜など）、住所→緯度経度（地図）、都道府県・市区町村のコード。
- **中止・延期の扱い**：最終確認日を、必ず表示。確認できないものは、「要確認」。
- 地図は、地域の入口として、強い（補助金ネットの日本地図と同じ考え方）。
- 収益（広告・アフィリエイト）と、免責（「開催の有無は、主催者の公式情報でご確認ください」）を、最初から書く。
